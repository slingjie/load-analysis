## 已确认口径与约束

- 策略构造（从格子到最多两次循环）：采纳“方案B：合并多段为两次（按时长/能量占比合并）”，并支持跨日拼接（当日末尾与次日开头若同类型则合并）。
- 计算口径：首期仅“窗口平均法（window_avg）”；SOC 逐点积分（step_15min）作为后续选项。
- TOU 电价来源：完全由“月→档位→价格”与“日期规则”驱动（使用当前程序前端配置/导入），不引入外部 JSON TOU。
- 报表输出：需要生成 Excel 报表与 TOU 配置快照（保存与下载机制由本方案提出并实现）。
- SOC 跨日结转：默认关闭；每日起点采用 `initial_soc=0.05`。
- 合并阈值：默认 30 分钟，并在前端开放可调参数。
- 能量公式默认值：physics（物理一致）。

## 接口契约（草案）

请求：`POST /api/storage/cycles`（multipart/form-data）
- `file`: 负荷文件（CSV/XLSX；列包含 `timestamp, load` 或 `timestamp, load_kw`）
- `payload`: JSON 字符串，结构：
  - `storage`: { capacity_kwh, c_rate, single_side_efficiency, depth_of_discharge, soc_min, soc_max, initial_soc, reserve_charge_kw, reserve_discharge_kw, metering_mode, transformer_capacity_kva, transformer_power_factor, calc_style: 'window_avg', energy_formula: 'physics'|'sample', soc_carry_over: false, merge_threshold_minutes?: number }
  - `strategySource`: { monthlySchedule, dateRules }（沿用前端 types.ts 的结构）
  - `prices`: MonthlyTouPrices（12 个月档位→价格）

响应：`CyclesResponse`
- `yearly_total_cycles: number`
- `monthly_cycles: Array<{ month: number, cycles: number, equivalent_cycles?: number, c1_full_charge_ratio?: number, c1_full_discharge_ratio?: number, c2_full_charge_ratio?: number, c2_full_discharge_ratio?: number, ... }>`
- `daily_cycles_head: Array<{ date: string, cycles: number, ... }>`（可返回全量或带分页/截断）
- `qc?: object`（缺价点位、缺失插值统计、掩码合并提示等）
- `excel_path?: string` 与（可选）`download_url?: string`
- （阶段C）`energy_trace?: Array<{ timestamp, cycle, action, power_kw, soc_start_kwh, soc_end_kwh, grid_import_kwh, grid_export_kwh, price? }>`

错误处理：
- 文件解析失败（400）
- 参数验证失败（400）
- 服务器内部错误（500）

## 策略构造：从格子到“两次循环”

目标：将任意“充/放”格子序列，规范化为最多两次循环（c1/c2）的“充电窗口与放电窗口”集合。

步骤：
1) 片段抽取：按 15 分钟粒度遍历 24h，识别“充/放/待机”连续片段；剔除长度为 0 的片段。
2) 跨日拼接：若当日末段与次日首段类型一致（充或放），将其合并为连续片段（保证跨午夜的连续性）。
3) 片段合并阈值：将时长小于阈值（默认 30 分钟）的微小片段，向相邻同类片段合并（优先与更长者合并）。
4) 两次限制：
   - 若仍超过 2 次循环：
     - 合并策略A：优先合并相邻同类型最短两段，直至最多两次循环；
     - 合并策略B：以“能量占比”作为权重（需 window_avg 或估算功率）合并影响最小的段。
   - 保证顺序：c1_charge → c1_discharge → c2_charge → c2_discharge；若缺失对应段，置空并在 QC 标注。
5) 冲突检测：若出现同时标记“充/放”的步长，记录为冲突并按“空动作”处理（window_avg 下对能量统计无影响，仅做 QC）。

输出：日掩码（c1/c2 × charge/discharge）与跨日拼接后的日序列。

## TOU 映射：从格子档位到时点价格

规则：
- 以每日 24h 格子中的 TOU 档位 + 当月价格表生成 `[start, end)` 段，并在 15 分钟时点上取价；
- 遇到价格缺失（null/NaN）时：
  - window_avg：窗口均价在缺价时点剔除该点（若全段均缺价则返回 None），并在 QC 记录缺价点位与说明；
  - （阶段C）step_15min：对能量轨迹中的购售电计算，缺价默认按 0 处理并统计缺价数用于 QC。

## 计算口径与结果

首期仅 window_avg：
- 许可功率：
  - 充电许可：`allow_ch = limit_kw - reserve_charge_kw - avg_load`
  - 放电许可：`allow_dis = avg_load - reserve_discharge_kw`
  - limit_kw 来源：按月需量口径或变压器容量（取决于 metering_mode）
    - 当 `metering_mode = 'monthly_demand_max'` 时，后端按每个月分别基于负荷数据自动统计“月最大需量（kW）”，无需前端传入；
    - 当 `metering_mode = 'transformer_capacity'` 时，按 `transformer_capacity_kva * transformer_power_factor` 计算上限。
- 电网侧能量（推荐 physics 口径）：
  - `E_in_grid = sum(allow_ch_clipped * hours) * DOD / η`
  - `E_out_grid = sum(allow_dis_clipped * hours) * DOD * η`
- 满充/放率与等效循环：
  - `full_charge_ratio = min(E_in_grid / capacity, 1)`；`full_discharge_ratio = min(E_out_grid / capacity, 1)`
  - `cycles_day = min(fc1_charge, fc1_discharge) + min(fc2_charge, fc2_discharge)`
- 汇总：日表、月汇总（含 cycles 与等效循环）、年累计；QC 包含缺价/缺失/掩码冲突等。

（阶段C）step_15min（简述）：逐 15 分钟步进，考虑 SOC 约束求解 `p_charge/p_discharge`，记录能量轨迹、SOC、购售电与净收益；与 window_avg 的 DOD 口径形成对照。

## 风险与缓解

- 多于两次循环的合并规则影响：通过“时长阈值 + 影响最小合并”降低偏差，并以 QC 提示用户优化策略。
- 价格缺失：窗口均价/轨迹计算兜底，保留明细以便审计。
- 非 15 分钟数据：按天重采样至 15 分钟；超阈值缺失段不插值并标记无效日。
- 计费口径差异：月需量与变压器容量两路实现，参数校验避免误配。

## 术语与能量公式说明（为“能量公式选择”提供直观说明）

- η（single_side_efficiency，单边效率）：充电进电池的能量需乘以 η，放电从电池出来的能量需除以 η 才到电网侧。
- DOD（depth_of_discharge，充放深度）：参与循环的容量占额定容量的比例。

两套“电网侧”换算口径：
1) physics（物理一致，推荐）
   - 充电：电网购电量 ≈ “窗口许可功率×时长（电池侧能量）× DOD / η”
   - 放电：电网售电量 ≈ “窗口许可功率×时长（电池侧能量）× DOD × η”
   - 解释：电池侧能量到电网侧，需要按效率在充/放两侧做对称换算；更符合能量守恒与工程直觉。
2) sample（样例法，用于对齐历史样例表格）
   - 充电：`E_in_grid = base / DOD * η`
   - 放电：`E_out_grid = base / DOD / η`
   - 解释：该口径用于复现历史样例/外部表格中的计算方式，非严格物理守恒。一般不建议作为默认口径。

建议：默认使用 physics；如需对照验收表格，可切换到 sample 并在 QC 标注。
