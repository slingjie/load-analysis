# 变更提案：迁移“储能充放次数测算”（window_avg MVP）

## 背景与目标
- 背景：现有系统已具备分时电价配置、充/放逻辑（格子编辑）、日期规则与负荷导入/分析能力。需要迁移参考程序的“储能充放次数测算”主功能（算法与结果展示），在不整体引入参考前端的前提下完成最小可用闭环。
- 目标：
  - 后端新增统一计算接口（multipart：负荷文件 + JSON 参数），实现 window_avg 计算口径并生成 Excel 报表与 TOU 配置快照；
  - 前端新增“储能测算页”，支持参数输入、文件上传、结果可视化与报表下载；
  - 默认口径：`calc_style=window_avg`、`energy_formula=physics`、`initial_soc=0.05`、`merge_threshold_minutes=30`、按需量模式（`monthly_demand_max`）时后端按月自动统计最大需量。

## 变更范围
- 后端
  - 新增 `POST /api/storage/cycles`：接收负荷文件（CSV/XLSX）与 JSON `payload`；输出年/月/日 cycles、QC、`excel_path`。
  - 策略与 TOU：从“月度格子 + 日期规则 + 月度价格”生成 c1/c2 两次循环的充/放掩码与 TOU 段价映射；缺价计入 QC。
  - 计算：实现 window_avg 口径（physics 默认），返回日/月/年汇总；
  - 报表：Excel 单文件多 Sheet（结果、TOU 快照、缺失/缺价明细），静态目录直连下载；
  - 性能：全年 96×365 在秒级~十秒级完成（视环境）。
- 前端
  - 新增 `StorageCyclesPage`：参数表单、文件上传、提交与渲染、QC 提示、图表（“月次数柱状 + 日次数折线”）与下载入口。
  - 复用现有 TOU 配置、日期规则与月度价格作为数据来源，避免新增外部 TOU 文件。

## 非目标
- 本变更不包含 step_15min（SOC 逐点积分）与收益/能量轨迹展示；如需将作为后续增强。
- 不引入新前端依赖（继续使用现有 ECharts 方式）。

## 里程碑
1) D+0：冻结接口与参数默认；
2) D+2：完成后端 window_avg 与报表导出；
3) D+4：完成前端测算页与联调；
4) D+6：文档与演示、收尾优化；

## 依赖与参考
- 价格/格子/日期规则来自当前系统前端配置；
- 参考程序（仅作算法与结构参考，不整体迁移 UI）：
  - `参考储能次数测算程序文件夹/1010储能容量匹配度评估模型claude`（或同名变体）
  - 关键文件：`app/services/compute.py`、`app/services/strategy.py`、`app/utils/tou.py`、`app/schemas.py`

## 风险与缓解
- 多于两次循环的合并可能带来偏差：采用“时长阈值 + 影响最小合并”，并在 QC 中提示；
- 价格缺失：均价剔除缺价步并保留缺价明细，QC 可复核；
- 非 15 分钟数据：按天重采样至 15 分钟，超阈值缺失段不插值并标记无效日；

## 验收标准（MVP）
- 与“迁移任务方案/验收要点与测试用例.md”一致：年累计循环数、月/日结果、QC 与报表导出通过；性能满足全年计算在秒级~十秒级；样例对拍一致。
