## ADDED Requirements

### Requirement: 新增 StorageCyclesPage（参数 + 上传 + 结果 + 下载）
系统应新增“储能测算页”，支持参数配置、负荷文件上传、提交计算、结果展示与报表下载。

#### Scenario: 参数表单
- 表单字段应至少包含：容量、倍率、效率、SOC 上/下限、`initial_soc`、余量、计费口径、能量公式（默认 physics）、跨日结转（默认关）、合并阈值（默认 30，可调）。
- 字段校验应在前端提供基础提示，默认值与后端一致。

#### Scenario: 文件上传与提交
- 用户选择 CSV/XLSX 负荷文件（包含 `timestamp, load` 或 `timestamp, load_kw`），
- 点击提交后，前端以 `multipart/form-data` 发送 `file` 与 `payload` 至后端，
- 异常时以消息或表单内提示反馈。

### Requirement: 结果展示（图表与统计）
系统应展示年累计次数、月度次数柱状图、日度次数折线图，并提供 QC 提示。

#### Scenario: 年/月/日可视化
- 当得到后端返回的 `days[]/months[]/year{}`，
- 页面应渲染头部“年累计循环数”，中部“月度次数柱状”和“日度次数折线”，
- 对异常/缺价/缺失以徽标或提示展示（来源于 `qc`）。

### Requirement: 报表下载入口
系统应提供报表下载入口，使用后端返回的相对路径进行静态直连下载。

#### Scenario: 下载链接可用
- 当返回 `excel_path` 时，
- 页面显示下载按钮，点击后可直接获取文件（浏览器下载）。

### Requirement: 交互与可用性
页面应在加载态、错误态、空数据态下有明确提示；不引入新前端依赖。

#### Scenario: 状态提示
- 提交后显示加载中；失败时以可读错误提示；无结果时引导用户上传文件与配置参数。
