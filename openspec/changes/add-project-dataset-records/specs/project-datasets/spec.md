## ADDED Requirements

### Requirement: 项目（Project）管理
系统 MUST 提供项目级的组织能力，用于归类多个负荷数据集与测算记录。

#### Scenario: 创建项目
- 用户输入项目名称并提交；
- 系统创建项目并在列表中可见；
- 若名称为空或重复（同一用户范围内），系统应提示并阻止提交（口径可实现时再细化）。

#### Scenario: 选择项目
- 用户选择某个项目后，
- 该项目下的数据集列表与保存入口应切换至对应项目。

#### Scenario: 默认本地模式
- 当系统未启用 Supabase 模式时，
- 项目数据应默认保存到本地持久化存储，且在刷新后仍可选择与使用。

### Requirement: 数据集（Dataset）保存
系统 MUST 支持将已清洗的负荷点位保存为“数据集”，并关联到项目。

#### Scenario: 从负荷分析结果保存
- 当用户已完成负荷分析，且存在 `cleaned_points/meta/report`，
- 用户点击“保存到项目”，输入数据集名称并提交，
- 系统应创建数据集元数据记录（包含时间范围、点数、采样间隔、质量报告与元信息），并将点位数据写入当前启用的持久化存储（默认本地，启用 Supabase 时为云端）。

#### Scenario: 本地优先保存
- 当系统未启用 Supabase 模式时，
- 系统应将点位与元信息保存到本地存储（优先 IndexedDB），并允许后续迁移到 Supabase。

#### Scenario: 保存成功提示
- 当保存成功时，
- 系统应提示成功并在数据集列表中可见。

#### Scenario: 保存失败提示
- 当保存失败（网络/权限/空间/服务异常）时，
- 系统应提示失败原因，并不影响用户继续使用当前会话内的数据进行测算。

### Requirement: 数据集列表与加载
系统 MUST 支持列出项目内数据集并加载到应用全局状态，供后续页面复用。

#### Scenario: 列表展示
- 当用户进入项目时，
- 系统应展示该项目下的数据集列表（至少包含：名称、时间范围、点数、创建时间）。

#### Scenario: 加载数据集
- 当用户选择某个数据集并点击“加载/使用”时，
- 系统应拉取点位数据并加载为应用的全局负荷序列，使“负荷分析页/储能测算页”等页面可直接引用。
