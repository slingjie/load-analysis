# 经济性报表导出功能 - 问题排查与解决

## 问题描述
前端调用导出API时出现 422 错误：
```
Failed to load resource: the server responded with a status of 422 (Unprocessable Entity)
[storageApi] exportEconomicsCashflowReport failed Object
```

## 问题原因

### 1. 语法错误（已修复）
**问题**：`backend/app.py` 第1239行有全角冒号 `：` 导致Python语法错误
**修复**：删除了错误的中文字符

### 2. 参数验证错误（已修复）
**问题**：前端可能传递 `null` 值给可选参数，但后端验证可能不接受 `null`
**修复**：修改前端代码，只在参数有有效值时才包含在请求体中

## 修复内容

### 后端修复 (backend/app.py)
1. 移除文档字符串外的中文内容
2. 改进错误日志，显示接收到的请求体keys
3. 在参数解析失败时记录完整的请求体

### 前端修复 (components/StorageEconomicsPage.tsx)
修改 `handleExportReport` 函数，只在可选参数有值时才添加：
```typescript
const input: StorageEconomicsInput = {
```

### API调用修复 (storageApi.ts)
改进错误处理，显示详细的422验证错误：
```typescript
if (response.status === 422 && result?.detail) {
  if (Array.isArray(result.detail)) {
    // FastAPI验证错误格式

```

## 使用建议

### 前端使用
确保在调用导出功能前：
1. 所有必填字段都有有效值
2. 数值字段不是 `NaN` 或 `null`
3. 用户分成比例在 0-100 之间
4. 后端服务正在运行（端口8002）

### 调试方法
如果遇到422错误：
1. 打开浏览器控制台查看详细错误
2. 检查 `requestBody` 日志，确认所有字段类型正确
3. 查看后端日志中的 "received body keys" 信息
4. 使用 `test_frontend_api_call.py` 测试API是否正常
