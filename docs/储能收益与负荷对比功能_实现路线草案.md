# 储能收益与负荷对比功能 - 实现路线草案

> 关联 PRD：`docs/储能收益与负荷对比功能 PRD.md`

本路线文档面向具体开发实现，按“后端 → 前端 → 验证”分阶段拆解工作内容，默认在现有代码基础上增量实现，保持向后兼容。

---

## 1. 总体技术方案概览

1. 在现有 `/api/storage/cycles` 的基础上扩展：
   - 复用现有 15 分钟负荷序列 `series_15m`、窗口信息 `daily_masks`、计费上限 `limit_info`。  
   - 在 window_avg 之外，增加 step_15min 逐点收益积分逻辑。  
   - 新增日/月/年级别的收益结构（`StorageProfit*` 系列），并挂到 `StorageCyclesDay/Month/Year` 上。

2. 新增独立曲线接口 `/api/storage/cycles/curves`：
   - 采用“无 task_id、无持久化”的方案：前端携带 payload + date，后端按日重算并返回原负荷与储能后负荷曲线及指标对比。  
   - 复用 cycles 的参数解析与负荷标准化逻辑，避免重复代码。

3. 前端增加独立页面 `StorageProfitPage`：
   - 新增导航入口“收益与负荷对比”。  
   - 通过已有的 TOU 配置 + 负荷分析结果调用后端接口，展示收益汇总与负荷曲线对比。  
   - 与 `energy_formula`（physics/sample）联动。

## 2. 后端实现路线

### 2.1 数据模型扩展（schemas.py）

文件：`backend/schemas.py`

1. 新增收益模型：
   - `StorageProfit`：年/月/日统一的收益结构。  
   - 字段：`revenue, cost, profit, discharge_energy_kwh, charge_energy_kwh, profit_per_kwh`。

2. 新增双口径容器模型：
   - `StorageProfitWithFormulas`：包含 `main / physics / sample` 三个可选字段。  
   - `main` 对应请求时的 `energy_formula`，`physics/sample` 作为对拍字段（可选实现）。

3. 扩展现有模型：
   - `StorageCyclesDay` 增加：`profit: Optional[StorageProfitWithFormulas] = None`。  
   - `StorageCyclesMonth` 增加同名字段。  
   - `StorageCyclesYear` 增加同名字段。  

> 注意：保持默认值和描述（Field 描述）为中文，确保原有字段完全兼容。

### 2.2 逐点收益计算逻辑（cycles.py）

文件：`backend/services/cycles.py`

目标：在现有 `compute_window_avg_days_with_debug` 与 step_15min 计算基础上，增加一个“逐点收益汇总”函数，供 app 层调用。

#### 2.2.1 识别可复用的 step_15min 逻辑

1. 现有 step_15min 代码：
   - 在 window_debug 计算中，已有：
     - `base_kwh_step15`
     - `e_grid_kwh_physics_step15`
     - `e_grid_kwh_sample_step15`
   - 对应逻辑中已经有“逐点允许功率序列 `allow_series` × 0.25h 积分”的实现。

2. 复用策略：
   - 不改变现有 window_debug 生成逻辑。  
   - 以新的函数，从 `series_15m` + `daily_ops` + `limit_info` + `storage_cfg` 出发，单独生成：  
     - 逐点储能功率序列 `p_batt(t)`（正负号约定与 PRD 一致）；  
     - 逐点电网侧功率 `p_in_grid/p_out_grid` 和电量 `e_in_grid/e_out_grid`；  
     - 日/月/年收益汇总。

#### 2.2.2 新增收益计算函数（示意）

建议新增函数：

```python
def compute_profit_summary_step15(
    series_15m: pd.DataFrame,
    daily_ops: Dict[str, List[str]],
    limit_info: Dict,
    storage_cfg: Dict,
    price_series: Optional[pd.DataFrame],
    energy_formula: str = "physics",
) -> dict:
    """
    返回:
      {
        "days": {date -> StorageProfit/main+physics/sample 对应的 dict},
        "months": {year_month -> ...},
        "year": {year -> ...},
      }
    """
```

实现要点：

1. 每日循环：按 date 逐日分片 `day_sub = series_15m[...]`，对应 `price_sub`。  
2. 对每个 15 分钟点，依据 `daily_ops[date_str][hour]` 判断当前为“充/放/待机”：
   - 充电：按 PRD 中公式计算 `p_batt(t) > 0`；  
   - 放电：`p_batt(t) < 0`；  
   - 待机：`p_batt(t) = 0`。  
3. 根据 `energy_formula` 计算 `p_in_grid/p_out_grid` 与 `e_in_grid/e_out_grid`。  
4. 结合 `price_series["price"]` 计算 `cost_t / rev_t / profit_t`。  
5. 按 PRD 4.4 汇总出日/月/年收益，并构造 `StorageProfit` 对应的 dict。
6. 可选：同时计算 physics/sample 双口径，填入 `StorageProfitWithFormulas` 的 `physics/sample` 字段。

#### 2.2.3 与 compute_storage_cycles 挂接

文件：`backend/app.py`，函数 `compute_storage_cycles`：

1. 在完成：
   - `series_15m` 构建、  
   - `limit_info` 计算、  
   - `daily_ops` / `daily_masks` 构建、  
   - `price_series` 构建  
   之后，调用 `compute_profit_summary_step15`。

2. 将返回的收益结果按日期/月/年映射回：
   - `StorageCyclesDay`：创建时传入 `profit` 字段；  
   - `StorageCyclesMonth` / `StorageCyclesYear` 同理。  

3. 对错误处理：
   - 若 `price_series` 为空或内部错误，允许收益字段为空，仅在 `qc.notes` 中追加提示。  
   - 确保原有 cycles 聚合逻辑在收益模块异常时仍能工作。

### 2.3 新增曲线接口 `/api/storage/cycles/curves`

文件：`backend/app.py`

1. 新增路由：

```python
@app.post("/api/storage/cycles/curves")
async def get_storage_curves(payload: CurvesPayload) -> StorageCurvesResponse:
    ...
```

> 注：也可以采用 `Form + str payload` 的形式，为了复用逻辑可与 `/api/storage/cycles` 保持类似写法。

2. 请求解析：
   - 解析 payload 中的：`storage`, `strategySource`, `monthlyTouPrices`, `points` 或上传文件。  
   - 复用 `compute_storage_cycles` 中的前置步骤：
     - `series_15m` 构建；  
     - `daily_ops`；  
     - `limit_info`；  
     - `price_series`。  

3. 目标日期筛选：
   - 根据 `date: "YYYY-MM-DD"` 生成当日时间范围 `[date, date+1)`，切片出：  
     - `day_series = series_15m[...]`；  
     - `day_price_series`；  
   - 再按收益函数中的逻辑得到：
     - 当日逐点 `p_grid_effect(t)`；  
     - `load_with_storage(t) = load_original(t) + p_grid_effect(t)`。

4. 构造响应：
   - `points_original`：来自 `day_series["load_kw"]`。  
   - `points_with_storage`：`load_with_storage(t)` 序列。  
   - `summary`：调用收益汇总函数对单日输出 `StorageProfit` 对象，并计算：
     - 最大需量前后值与差值/比例；  
     - 分 TOU 档的电量、电费统计。  

5. Pydantic 响应模型：
   - 视需要在 `schemas.py` 新增 `StorageCurvesResponse`，或在 app 内部直接用 dict 返回。  
   - 推荐使用模型以保持类型一致性。

## 4. 验证与回归检查

### 4.1 功能验证场景

1. **基础流程**：
   - 上传一年的负荷数据，配置 TOU 与储能参数；  
   - 先在 StorageCycles 页面确认 cycles 与尖段占比结果正常；  
   - 切换到 StorageProfit 页面，查看年度/月份收益汇总是否显示；  
   - 选择一日查看负荷曲线与收益对比。

2. **energy_formula 切换**：
   - 在相同配置和负荷下，切换 physics / sample：  
     - 验证 cycles 仍基于 window_avg，主数值随 energy_formula 改变但逻辑一致；  
     - 验证收益统计与物理直觉一致（效率、DOD 越高，收益变化合理）。

3. **缺价点场景**：
   - 故意留空某些月份的部分 TOU 价格；  
   - 验证：收益会略有缺失，但不会报错；  
   - `qc.missing_prices` 有计数，页面有友好提示。

4. **极端场景**：
   - 全年负荷几乎为 0；  
   - 储能容量远大于负荷；  
   - 仅少量尖段有放电窗口；  
   - 确保不出现 NaN/Infinity，收益为 0 或合理的极小值。

### 4.2 回归要求

1. 在未访问 StorageProfit 页、或后端收益函数关闭的情况下：
   - `/api/storage/cycles` 原有字段的数值与之前版本完全一致。  

2. 对历史 Excel 报表：  
   - 确认新增列不会破坏原有列顺序或含义，或通过新 Sheet/新文件导出方式隔离。  

3. 错误处理：  
   - 曲线接口失败时，StorageProfit 页只提示“曲线加载失败”，不影响现有页面使用。

## 5. 分阶段实施建议

为降低风险，可分两期实施：

1. **第一期（必做）**：
   - 后端：完成 `/api/storage/cycles` 收益字段（不实现 `/curves`）。  
   - 前端：在新页面中仅展示日/月/年收益汇总表，不做曲线对比。  

2. **第二期（增强）**：
   - 后端：实现 `/api/storage/cycles/curves`，支持逐日曲线与指标对比。  
   - 前端：接入曲线接口，增加双曲线图和前后对比表。  

视开发节奏，可以优先上线第一期，让业务方先对收益口径进行对拍，再逐步加入负荷曲线展示。**
