# 产品需求文档（PRD）：项目经济性评估报告 v3.0（图文 PDF，一键下载）

| 版本 | 日期 | 作者 | 变更说明 |
| --- | --- | --- | --- |
| v3.0 | 2025-12-14 | 系统架构师 | 按真实使用流程重构；图文并茂 PDF 一键导出；典型日规则明确；AI 文案润色可选；明确本期不含 NPV |

---

## 1. 背景与问题

当前系统报告能力主要为“纯文本 Markdown（LLM 生成）”，存在以下问题：

1. **交付不专业**：客户侧更需要版式规范、图文并茂、可直接投标/汇报的 PDF 报告。
2. **流程不强绑定**：报告结构未严格对齐用户实际操作流程（新建项目→TOU/策略→负荷导入→负荷分析→最优 cycles→经济性→输出报告）。
3. **数据可追溯弱**：刷新/跳转导致状态丢失时，报告容易出现“数据为 0”，缺少“数据快照 + 缺失项提示”的硬约束。
4. **图表缺失**：负荷、TOU、策略、容量对比、现金流等核心信息必须通过图表呈现。

---

## 2. 目标（必须达成）

1. **一键下载 PDF**：用户在页面点击“导出 PDF”，浏览器直接下载 `.pdf` 文件，无需手动打印。
2. **图文并茂**：报告包含封面/页眉页脚/关键指标卡/图表/表格/结论与风险提示/附录。
3. **流程对齐**：报告章节结构与用户操作流程一致（章节顺序即工作流顺序）。
4. **数据自动汇集**：报告数据默认从系统已计算结果与配置中获取；对必须用户填写的数据，界面必须高亮提示。
5. **缺失数据可控**：允许缺数据导出，但必须（a）导出前给出缺失项清单；（b）报告对应章节标注“未配置/未测算/数据不足”。
6. **AI 文案润色可选**：开关关闭时输出模板化文字；开关开启时对“摘要/结论/风险/建议”做润色，但禁止编造任何数值。

---

## 3. 非目标（本期不做）

1. 拖拽式自由排版模板编辑器
2. Word 导出
3. 多项目批量生成
4. 复杂多维敏感性分析（如 Monte Carlo）。本期仅做“可选的 ±10% 情景”预留或不做。

---

## 4. 用户工作流（基线）

1) 新建项目  
2) 配置 TOU 与储能充放逻辑  
3) 导入负荷数据（含质量诊断/清洗）  
4) 查看负荷分析（负荷统计、典型曲线、月度分布等）  
5) 最优 cycles 测算（含容量对比）  
6) 经济性测算（现金流、IRR、回收期、LCOE、度电收益等）  
7) 输出报告（图文 PDF）

---

## 5. 功能范围（v3.0）

### 5.1 与原功能配合方式（方案 A：双轨并行，推荐）

为降低上线风险、保留既有能力，本期采用 **方案 A（双轨并行）**：

1. **保留原“Markdown 报告（旧）”能力**  
   - 现有页面与接口保持不变（用于生成纯文本 Markdown 报告初稿）。  
   - 作为“快速文字报告/AI 初稿”入口继续提供给用户。
2. **新增“PDF 报告中心（新）”能力**  
   - 新增独立入口/页面用于生成图文并茂 PDF，并支持一键下载与报告快照。  
   - 作为“正式交付报告”入口提供给用户。

**原则**：
- 新功能上线不影响旧流程；旧功能作为兜底与对照。
- 待 PDF 链路稳定后，再评估是否在后续版本下线/隐藏旧功能（不在 v3.0 范围内）。

### 5.2 新增：PDF 报告中心（新）

**入口位置建议**：导航栏新增“报告中心”或将现 `ProjectSummaryPage` 升级为“报告中心（含 PDF 导出）”。

**页面能力**：

1. **数据源选择**
   - 选择项目（Project）
   - 选择数据集（Dataset）
   - 选择运行快照（Run）：cycles/profit/economics（默认选择最近一次完整运行）
2. **完成度检查**
   - TOU 是否配置完整
   - 负荷数据是否导入且有有效数据
   - cycles 是否已计算（含年等效循环、首年收益/放电能量）
   - economics 是否已计算（IRR/回收期/现金流/静态指标）
3. **报告参数填写区（含校验）**
   - 必填：**项目总投资（万元）**
   - 选填：业主方名称、项目地点、编制单位/作者、封面副标题、Logo
4. **AI 文案润色开关**
   - 关闭：模板化文字（不依赖外网/密钥）
   - 开启：调用 LLM 进行润色（受约束：禁止编造数值）
5. **预览与导出**
   - A4 预览（分页、页眉页脚、目录可选）
   - 一键导出 PDF（直接下载）
   - 保存“报告快照”（可重复导出，保证可追溯）

### 5.2 典型日选取规则（已确认）

报告必须包含两类典型日（至少 2 页内容，图表 + 解读）：

1. **收益最高日**：在 cycles 日度结果中，选择 `day.profit.main.profit` 最大的日期作为“收益最高日”。
2. **最大负荷日**：在负荷点位中按日期聚合，选择 `max(load)` 最大的日期作为“最大负荷日”。

**冲突与兜底**：
- 若两者为同一天：仅展示一次，但需在标题注明“收益最高日（同时为最大负荷日）”。
- 若某类无法计算（缺 cycles 或缺负荷点位）：该类典型日章节保留占位并标注“未测算/数据不足”，同时在导出前缺失项清单提示。
- 允许用户手动替换日期（可选增强）：下拉选择其他日期并重新生成典型日图表。

## 6. 经济性指标口径（已确认）

报告固定输出以下指标（均需与系统计算结果一致）：

- IRR（内部收益率）
- 静态回收期（年）
- LCOE（静态平均度电成本）
- 度电收益（度电平均收益）
- 等效循环次数（年等效 cycles）
- 放电能量（首年放电能量 kWh）
- 项目期末累计净现金流（不折现，单位：元）

### 6.1 指标来源映射（从程序获取）

1. **等效循环次数 / 首年收益 / 放电能量**
   - 来源：cycles 结果（年汇总/日汇总）
   - 字段示例：`year.cycles`、`year.profit.main.profit`、`year.profit.main.discharge_energy_kwh`
2. **IRR / 静态回收期 / 现金流序列**
   - 来源：economics 结果
3. **LCOE / 度电收益**
   - 来源：economics 结果的 `static_metrics`（若缺能量输入则必须提示“静态指标置信度不足/使用降级口径”）
4. **累计净现金流（不折现）**
   - 来源：economics 结果的 `final_cumulative_net_cashflow`

### 6.2 不含 NPV（说明）

- v3.0 不计算/不输出 NPV（净现值），报告以“年度现金流序列 + 项目期末累计净现金流（不折现）”作为补充呈现。
- 如后续需要 NPV，将在 economics 输入中增加 `discount_rate` 并在输出中增加 `npv`，同时在报告中展示折现率口径。

## 7. PDF 报告结构（章节＝工作流）

### 封面
- 标题：`[业主方名称] 储能项目经济性评估报告`
- 副标题：`基于 [项目名称] 的模拟分析`（可编辑）
- 信息：项目地点、评估周期、报告日期（自动）、编制单位/作者、版本号、Logo（可选）

### 第 1 章 项目与数据概况（新建项目 + 导入负荷）
- 1.1 项目基本信息（表格）
- 1.2 数据来源与周期（表格：数据集名称/文件名/起止/采样间隔/点数）
- 1.3 数据质量摘要（缺失天/缺失小时/异常值占比 + “对结论影响”提示）

### 第 2 章 TOU 与运行策略配置（配置 TOU + 充放逻辑）
- 2.1 分时电价配置  
  - 图：24h 分时电价图（阶梯/柱状）
  - 表：尖/峰/平/谷/深价格（按月/按规则取最常用口径；详细表放附录）
- 2.2 运行策略配置  
  - 图：24h 运行策略色块图（充/放/待机）
  - 文字：策略说明（模板化，AI 可润色）
- 2.3 储能系统关键参数（表格：容量、功率/倍率、效率、SOC、预留功率、计量口径等）

### 第 3 章 负荷特性分析（负荷分析）
- 3.1 关键统计指标卡：平均/最大/最小/峰谷差
- 3.2 典型曲线（图）：工作日/周末平均（若已具备）或月均日曲线
- 3.3 月度分布（图）：月均负荷/峰值分布
- 3.4 负荷与电价叠加（图）：负荷-电价叠加，体现套利窗口

### 第 4 章 最优 cycles 与容量建议（最优 cycles）
- 4.1 基准方案结果（表 + 指标卡）：年等效 cycles、首年收益、首年放电能量、有效天数
- 4.2 容量对比（若用户做过批量容量对比）
  - 图：容量-循环趋势、容量-收益趋势（双轴或两张图）
  - 表：各档容量 cycles/收益/推荐标记
- 4.3 推荐容量与理由（模板化 + AI 可润色）

### 第 5 章 经济性测算与回收期（经济性）
- 5.1 指标卡：IRR、静态回收期、LCOE、度电收益、项目期末累计净现金流
- 5.2 现金流图：年度净现金流柱状 + 累计现金流折线（标注回收期）
- 5.3 现金流明细表（表）：年度收益、运维、更换电芯（如有）、净现金流、累计净现金流
- 5.4 静态筛选结果（如有）：`LCOE 比值`、筛选结论（pass/fail）

### 第 6 章 结论与风险提示（报告输出）
- 6.1 综合结论（必须引用系统数值；AI 仅润色措辞）
- 6.2 风险提示（电价政策/负荷波动/数据代表性/衰减与运维）
- 6.3 建议与下一步（模板化；AI 可润色）

### 附录
- A. TOU 明细表（按月/规则）
- B. 数据质量明细（缺失分月、异常片段摘要）
- C. 关键参数清单（用于可追溯）

## 10. 技术方案（满足“一键下载 PDF”）

### 10.1 推荐方案：后端 Headless Chromium 生成 PDF（稳定、可控）

**核心思路**：
1. 前端在“报告预览”中完成布局与图表渲染；
2. 前端将“报告数据 JSON + 图表图片（base64）+ 用户填写项 + AI 开关”提交后端；
3. 后端基于固定 HTML 模板渲染（嵌入图片/表格），用 Headless Chromium（Playwright/Chromium）导出 PDF；
4. 后端返回 `application/pdf`，前端直接下载。

**优点**：分页稳定、字体与边距一致、客户交付一致性最好。  
**注意**：需确保部署环境可运行 Chromium；字体/中文支持需验证。

### 10.2 不实现 NPV（范围说明）

- v3.0 不包含 NPV 计算与输出；PDF 中不展示 NPV 字段与折现率输入项。

### 10.3 AI 文案润色（可选开关）

**开关关闭**：完全模板化文字（保证离线可用）。  
**开关开启**：调用 LLM（例如 DeepSeek），但必须满足：
- 仅允许润色“摘要/结论/风险/建议”等自然语言段落；
- **禁止编造具体数值**，所有数值必须来自结构化数据；
- 数据缺失时必须输出“数据不足/未测算”，不得虚构。

## 11. API 需求（建议）

### 11.1 生成 PDF

`POST /api/report/pdf`

**请求体（建议）**：
- `report_meta`：项目名称、业主方、地点、周期、版本、作者、Logo 等
- `report_data`：负荷统计、TOU、策略、cycles、economics 等结构化数据
- `chart_images`：键值对（chart_id → base64 PNG）
- `ai_polish`：boolean

**响应**：
- `200 application/pdf`：PDF 二进制
- `4xx`：缺失项/校验错误

### 11.2（可选）预览/调试

`POST /api/report/html` 返回 HTML（用于调试排版与模板）

## 12. 验收标准（可测试、可复现）

1. **一键下载**：点击“导出 PDF”后，浏览器直接下载 `.pdf`，不依赖手动打印。
2. **图表完整**：至少包含第 8 节所列的“最小必备图表”中的 6 张；两类典型日必须出现（能算出来时）。
3. **数值一致**：报告中的 IRR、回收期、LCOE、度电收益、等效循环、放电能量、项目期末累计净现金流，与页面/接口返回值一致。
4. **缺失可控**：在缺 cycles/缺经济性/缺典型日的情况下：
   - 导出前出现缺失项清单提示
   - 报告对应章节显示“未测算/数据不足”，而不是 0 或编造内容
5. **AI 可控**：AI 开关开启时仅改变措辞，不改变数值；关闭时不调用外网也可导出。

---

## 13. 风险与对策

1. **中文字体/分页不一致**：优先后端 Chromium 生成；锁定字体与页面边距；提供回归用的基准 PDF。
2. **图表清晰度**：统一导出为 2x/3x 分辨率 PNG；大表格分页需模板支持。
3. **数据口径冲突（kW/kWh）**：报告中所有单位必须在字段旁明确展示，并在附录给出口径说明；如当前数据字段含义不确定，必须在开发阶段统一字段命名与单位。
4. **外网依赖**：报告生成禁止依赖 CDN（如 ECharts CDN）；需将依赖本地化，保证离线可用。
