## 1. 需求背景

### 1.1 当前状态

## 1.1 当前状态

系统已实现以下功能：

1. **StorageCyclesPage（储能次数测算页）**
   - ✅ 单次测算模式：给定容量，计算循环数和收益
   - ✅ 批量容量对比模式：对比不同容量的"全年等效循环数"和"首年收益"
   - ✅ 反推容量功能：根据目标循环数反推最优容量

2. **StorageEconomicsPage（储能经济性测算页）**
   - ✅ IRR（内部收益率）计算
   - ✅ 静态回收期计算
   - ✅ 年度现金流序列展示
   - ⚠️ 需要用户手动输入参数，无法与批量容量对比联动

3. **BatchCapacityChart（批量容量对比图表）**
   - ✅ 显示容量 vs 循环数曲线
   - ✅ 显示容量 vs 首年收益曲线
   - ❌ 缺少回收期维度

### 1.2 存在问题

1. **决策维度单一**：批量对比只看循环数和首年收益，无法评估投资回收风险
2. **页面割裂**：经济性分析需要在另一个页面手动输入，无法快速对比不同容量的经济性
3. **决策困难**：容量大循环数多不一定收益最优，用户缺少"回收期"这一关键决策指标

### 1.3 用户需求

用户希望在批量容量对比时，能同时看到：
- **循环数**：反映储能系统利用率
- **首年收益**：反映短期收益能力
- **静态回收期**：反映投资回收速度（新增 ⭐）
- **IRR**：反映项目综合回报率（可选）

通过多维度对比，让用户能够综合判断：
- 哪个容量利用率最高（循环数最多）
- 哪个容量短期收益最好（首年收益最高）
- **哪个容量回收最快（回收期最短）** ⬅️ 核心新增需求

## 2. 功能设计

### 2.1 总体方案

**方案选择**：集成方案（方案1）

在现有 StorageCyclesPage 的批量模式中集成经济性计算，一站式展示全部关键指标。

**优势**：
- ✅ 用户体验最佳：无需页面切换
- ✅ 开发成本适中：复用现有 API 和组件
- ✅ 逻辑内聚：批量对比与经济性分析本质是同一个决策流程

**劣势**：
- ⚠️ 需要用户配置经济性参数（通过合理默认值缓解）
- ⚠️ 计算量增加（通过异步批量处理优化）

### 2.2 数据结构设计

#### 2.2.1 扩展 BatchCapacityItem 接口

```typescript
interface BatchCapacityItem {
  // 原有字段
  capacityKwh: number;                              // 容量（kWh）
  yearEqCycles: number;                             // 全年等效循环数
  firstYearProfit: number;                          // 首年收益（元）
  response: BackendStorageCyclesResponse | null;    // cycles API 响应
  status: 'pending' | 'computing' | 'done' | 'error';
  errorMsg?: string;

  // 新增经济性字段 ⭐
  irr?: number;                                     // 内部收益率（0-1，如 0.12 表示 12%）
  staticPaybackYears?: number;                      // 静态回收期（年）
  capex?: number;                                   // 总投资（元）
  economicsResult?: StorageEconomicsResult;         // 完整经济性结果（可选，用于详情展示）
}
```

#### 2.2.2 新增经济性参数配置

```typescript
interface EconomicsParams {
  // 投资成本
  capexPerWh: number;                    // 单位容量投资成本（元/Wh），默认 1.0
  
  // 项目参数
  projectYears: number;                  // 项目年限，默认 15
  
  // 运维成本
  omCostRatio: number;                   // 年运维成本占 CAPEX 比例，默认 0.015 (1.5%)
  
  // 衰减参数
  firstYearDecayRate: number;            // 首年衰减率，默认 0.03 (3%)
  subsequentDecayRate: number;           // 后续年衰减率，默认 0.02 (2%)
  
  // 电芯更换（可选）
  cellReplacementYear?: number;          // 电芯更换年份（如第 8 年）
  cellReplacementCostRatio?: number;     // 更换成本占初始 CAPEX 比例，默认 0.4 (40%)
}
```

### 2.4 计算流程设计

#### 2.4.1 批量测算流程

```
用户点击"开始批量测算"
  ↓
遍历容量范围 [起始, 起始+步长, 起始+2*步长, ...]
  ↓
对每个容量 capacity_kwh:
  ├─ Step 1: 调用 POST /api/storage/cycles
  │          计算循环数和首年收益
  │          更新状态: computing → done
  │
  └─ Step 2: 如果启用经济性分析
             ├─ 计算总投资: capex = capacity_kwh * capexPerWh
             ├─ 调用 POST /api/storage/economics
             │  输入: {
             │    firstYearRevenue: cycles响应中的首年收益,
             │    projectYears,
             │    capex,
             │    omCostRatio,
             │    decayRates,
             │    ...
             │  }
             └─ 获取: irr, staticPaybackYears
  ↓
所有容量计算完成
  ↓
渲染图表和表格
```

#### 2.4.2 API 调用示例

**Step 1: 计算 cycles**

```typescript
const cyclesPayload: StorageParamsPayload = {
  storage: {
    capacity_kwh: 5000,
    c_rate: 0.5,
    // ... 其他参数
  },
  strategySource: { monthlySchedule, dateRules },
  monthlyTouPrices: prices,
  points: cleanedLoadPoints,
};

const cyclesResponse = await computeStorageCycles(file, cyclesPayload);
const firstYearProfit = cyclesResponse.summary_years[0]?.profit_net ?? 0;
```

**Step 2: 计算 economics**

```typescript
const economicsInput: StorageEconomicsInput = {
  capacity_kwh: 5000,
  first_year_revenue: firstYearProfit,
  project_years: 15,
  capex_per_wh: 1.0,
  om_cost_ratio: 0.015,
  first_year_decay_rate: 0.03,
  subsequent_decay_rate: 0.02,
  // 可选
  cell_replacement_year: 8,
  cell_replacement_cost_ratio: 0.4,
};

const economicsResult = await computeStorageEconomics(economicsInput);
// 获取: economicsResult.irr, economicsResult.static_payback_years
```

### 2.7 综合建议算法

#### 2.7.1 推荐逻辑

系统自动识别以下"最优点"：

1. **循环数最优**：`yearEqCycles` 最大值
2. **收益最优**：`firstYearProfit` 最大值
3. **回收期最优**：`staticPaybackYears` 最小值（新增 ⭐）
4. **IRR 最优**：`irr` 最大值

#### 2.7.2 决策建议文案

根据不同场景生成建议：

**场景 1：回收期最优 = 循环数最优**
```
💡 建议选择 6500 kWh
该容量同时达到最多循环数和最短回收期，综合性价比最高。
```

**场景 2：回收期最优 ≠ 循环数最优**
```
💡 决策参考:
• 如果优先考虑投资安全，建议 5500 kWh（回收期 5.1 年）
• 如果优先考虑长期收益，建议 7000 kWh（循环数 361 次/年）
```

**场景 3：多个容量回收期接近**
```
💡 5500 kWh、6000 kWh 回收期接近（均约 5.2 年）
建议选择 6000 kWh，循环数更高（342 vs 328）。
```

### 4.3 性能优化

**并发控制**：
```typescript
// 限制并发度为 3
const concurrency = 3;
const chunks = chunkArray(capacities, concurrency);
for (const chunk of chunks) {
  await Promise.all(chunk.map(cap => computeSingleCapacity(cap)));
}
```

**缓存策略**：
- 相同容量、相同参数的计算结果缓存（sessionStorage）
- 用户修改参数后清空缓存

## 6. 风险与限制

### 6.1 已知风险

1. **计算时间翻倍**：每个容量需调用两次 API
   - **缓解措施**：异步并发 + 进度反馈

2. **参数配置复杂**：用户可能不理解经济性参数
   - **缓解措施**：提供预设方案 + 工具提示

3. **图表拥挤**：三条曲线可能重叠
   - **缓解措施**：双 Y 轴分离 + 交互式图例

### 6.2 功能限制

1. **不支持动态电价**：经济性计算基于首年收益外推，未考虑未来电价变化
2. **不支持多场景对比**：仅支持单一 TOU 排程的批量容量对比
3. **不支持敏感性分析**：未提供参数敏感性分析（如投资成本 ±10%）
