## 一、需求背景

### 1.1 问题分析

当前 Storage Cycles 计算直接使用原始数据，存在以下问题：

| 异常类型 | 对充电次数影响 | 对放电次数影响 | 当前处理 |
|---------|--------------|--------------|---------|
| **空值** | 不参与 | 不参与 | ✅ 已排除 |
| **零值** | 可能高估 | **严重低估（趋近0）** | ❌ 无处理 |
| **负值** | 可能高估 | **严重低估（趋近0）** | ❌ 无处理 |

### 1.2 业务场景说明

- **零值**：可能是"正常停机"（夜间、节假日），需用户判断
- **负值**：存在"反向送电"场景，应保留
- **空值**：数据缺失，需插值补全

### 2.5 等效循环次数处理

#### 2.5.1 当前计算公式

```
月等效循环数 = (月内实际循环数总和 / 有效天数) × 当月天数
年等效循环数 = Σ(12个月的等效循环数)
```

#### 2.5.2 清洗对等效循环的影响

- 清洗后数据更完整，等效循环的"估算误差"会减小
- 等效值可能降低（因为补全的数据可能低于平均值）
- **不删除等效循环**，但调整展示方式

#### 2.5.3 展示策略

1. **结果页面**：同时展示"实际循环总数"和"等效循环数"
2. **对比视图**：两种口径都进行对比
3. **智能提示**：
   - 数据完整度 ≥ 95%：提示"实际循环数更可靠"
   - 数据完整度 < 95%：等效循环数仍有参考价值

## 三、数据结构设计

### 3.1 零值时段详情

```typescript
interface ZeroSpanDetail {
  id: string;
  startTime: string;          // "2024-08-15T02:00:00"
  endTime: string;            // "2024-08-15T06:00:00"  
  durationHours: number;      // 4
  
  // 周边数据参考
  prevDayAvgLoad: number | null;     // 前一天同时段平均负荷
  nextDayAvgLoad: number | null;     // 后一天同时段平均负荷
  prevMonthSameDayAvgLoad: number | null;  // 上月同日平均负荷
  nextMonthSameDayAvgLoad: number | null;  // 下月同日平均负荷
  
  // 日期标签
  weekday: string;            // "周二"
  isHoliday: boolean;         // 是否节假日
  
  // 用户判断
  userDecision: 'normal' | 'abnormal' | null;
}
```

### 3.2 负值时段详情

```typescript
interface NegativeSpanDetail {
  id: string;
  date: string;
  startHour: number;
  endHour: number;
  minValue: number;           // 最小负值
  maxValue: number;           // 最大负值（绝对值最小的负值）
  pointCount: number;         // 点数
  treatment: 'keep' | 'abs' | 'zero';  // 处理方式
}
```

### 3.3 清洗配置（全局策略）

```typescript
interface GlobalCleaningPreferences {
  // 空值策略
  nullStrategy: 'interpolate' | 'delete' | 'keep';
  
  // 负值策略  
  negativeStrategy: 'keep' | 'abs' | 'zero';
  
  // 零值默认判断
  zeroDefaultDecision: 'ask' | 'normal' | 'abnormal';
  zeroThresholdHours?: number;  // 超过N小时默认标记为正常停机
  
  // 是否自动应用（跳过确认弹窗）
  autoApply: boolean;
  
  // 最后更新时间
  lastUpdated: string;
}
```

## 四、插值方案

### 4.1 自适应插值策略

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  📐 空值插值方案                                                            │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  采用 "分段线性插值 + 边界外推" 组合策略:                                    │
│                                                                             │
│  1️⃣ 短时间缺失 (≤4小时): 线性插值                                          │
│     已知点之间线性连接                                                      │
│                                                                             │
│  2️⃣ 中等缺失 (4~24小时): 同时段历史均值                                     │
│     参考: 前一天 + 后一天同时段，取平均                                     │
│                                                                             │
│  3️⃣ 长时间缺失 (>24小时): 同周几 + 同月历史加权                             │
│     参考: 最近4个同周几的同时段平均，越近权重越高                           │
│                                                                             │
│  4️⃣ 边界缺失 (数据首尾): 最近有效值外推                                     │
│     使用边界日同时段值填充，标记为"外推值"                                  │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 插值结果标记

插值后的数据点会被标记 `is_interpolated: true`，便于：
- 在图表中区分显示
- 在报告中说明数据来源
- 用户了解哪些数据是补全的
