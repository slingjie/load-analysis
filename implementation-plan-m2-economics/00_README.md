## 🎯 核心需求概括

### 背景
用户需要对不同容量的储能系统进行**批量经济性对比**，从而快速找到最优的投资方案。

### 删除内容
❌ **"尖段优先"(Price-Priority) 放电策略** — 已删除，改用程序当前时序计算结果

### 核心特性
1. ✅ **分离设计** — 三个独立 Tab（储能参数、批量对比、经济性分析）
2. ✅ **快速预设** — 一键应用"保守/标准/乐观"三套预设方案
3. ✅ **对比篮** — 支持选中 2-5 个容量做并排对比
4. ✅ **跨 Tab 导航** — 批量对比 → 点击行 → 自动导航到经济性分析

## 🔧 技术方案总结

### 架构图

```
┌──────────────────────────────────────────────────────┐
│                   UI 层 (React)                       │
│  StorageParamsPage  StorageCyclesPage  StorageEconomicsPage
│     (储能参数)         (批量对比)          (经济性分析)
└─────────────────┬────────────────────────────────────┘
                  │
┌─────────────────▼─────────────────────────────────┐
│        useStorageAnalysis Hook                     │
│  全局状态管理 + 数据共享 + 状态更新              │
│  • batchResults[]                                 │
│  • economicsParams                                │
│  • comparisonBasket (Set)                        │
│  • selectedCapacityForEconomics                   │
└─────────────────┬─────────────────────────────────┘
                  │
┌─────────────────▼─────────────────────────────────┐
│        API 调用层                                  │
│  • POST /api/storage/cycles (批量计算)            │
│  • POST /api/storage/economics (经济性分析)       │
└──────────────────────────────────────────────────┘
```

### 关键技术点

1. **并发度控制** — 批量计算并发度 3，避免超载
2. **状态管理** — useStorageAnalysis Hook，实现全局状态共享和持久化
3. **跨 Tab 导航** — 使用 React Router location.state 传递导航参数
4. **图表库** — Chart.js（已有依赖）
5. **样式架构** — CSS 变量 + BEM 命名规范

5. **及时反馈** — 有疑问立即与产品/设计沟通 ✅

### 潜在风险与缓解

| 风险 | 概率 | 缓解措施 |
|------|------|---------|
| API 返回格式变化 | 低 | 与后端提前确认 schema，预留兼容性处理 |
| 批量计算超时（10+ 容量） | 中 | 实现并发度限制 + 超时重试机制 |
| 跨浏览器兼容性 | 中 | 提前在主流浏览器测试，使用 polyfill |
| 性能瓶颈（大表格） | 低 | 如需支持 1000+ 行，使用虚拟列表 (react-window) |

### 时间管理建议

- **第 1 天** — M1 + M2.1-2.3 (数据层 + UI 基础)
- **第 2 天** — M2.4-3.3 (增强组件 + 图表)
